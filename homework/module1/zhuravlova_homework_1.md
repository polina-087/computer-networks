## Завдання 1. Дослідження мережі (2 бали)

**Команда:**
```bash
ip a
```

**Результат для мережевого інтерфейсу eth0:**
```text
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 00:15:5d:b3:e4:75 brd ff:ff:ff:ff:ff:ff
    inet 172.29.238.42/20 brd 172.29.239.255 scope global eth0
    inet6 fe80::215:5dff:feb3:e475/64 scope link
```

**Аналіз результатів:**

- **Інтерфейс:** eth0.
- **Тип підключення:** віртуальний Ethernet-адаптер у середовищі WSL 2.
- **MAC-адреса:** 00:15:5d:b3:e4:75 (канальний рівень OSI, Layer 2).
- **IPv4-адреса:** 172.29.238.42 (мережевий рівень OSI, Layer 3).
- **Маска підмережі:** 255.255.240.0, або /20 (мережевий рівень OSI, Layer 3).
- **Адреса мережі:** 172.29.224.0/20.
- **Шлюз за замовчуванням (gateway):** 172.29.224.1.
- **Широкомовна адреса (broadcast):** 172.29.239.255.
- **Кількість доступних адрес хостів (hosts):** 4094.

**Розрахунок кількості хостів:**

Адреса IPv4 містить 32 біти. Префікс /20 означає, що для хостів залишається 12 бітів. Кількість адрес у підмережі становить 2^12 = 4096. Після виключення адреси мережі та широкомовної адреси отримуємо 4094 доступні адреси хостів.

## Завдання 2. Дослідження маршрутизації (2 бали)

**Команда:**
```bash
ip r
```

**Результат:**
```text
default via 172.29.224.1 dev eth0 proto kernel
172.29.224.0/20 dev eth0 proto kernel scope link src 172.29.238.42
```

**Аналіз результатів:**

Перший маршрут є маршрутом за замовчуванням: пакети до інших мереж надсилаються через шлюз 172.29.224.1 та інтерфейс eth0.

Другий маршрут описує безпосередньо підключену мережу 172.29.224.0/20. Для передавання пакетів у цій мережі використовується інтерфейс eth0 з локальною IP-адресою 172.29.238.42.

Позначення `proto kernel` означає, що маршрут було додано ядром Linux. Воно не означає, що IP-адресу отримано через протокол DHCP.

**Протокол отримання IP-адреси:** Ubuntu працює в середовищі WSL 2, де мережеве підключення налаштовується віртуальною мережевою інфраструктурою Windows. За результатами виконаних команд точний протокол призначення IPv4-адреси не підтверджений. Служба systemd-networkd не керує інтерфейсом eth0.

## Завдання 3. Знаходження публічної IP-адреси (2 бали)

**Команда:**
```bash
curl ifconfig.io
```

**Результат:**
```text
89.215.209.207
```

**Порівняння локальної та публічної IP-адрес:**

- **Локальна IP-адреса:** 172.29.238.42.
- **Публічна IP-адреса:** 89.215.209.207.
- **Чи однакові адреси?** Ні, адреси різні.

**Пояснення:**

Локальна адреса 172.29.238.42 належить до приватного діапазону IP-адрес і використовується всередині віртуальної мережі WSL 2. Вона не маршрутизується безпосередньо через глобальний Інтернет.

Публічна адреса 89.215.209.207 — це адреса, яку зовнішній сервіс бачить під час отримання запиту.

Ubuntu працює всередині Windows через WSL 2. Її мережевий трафік проходить через віртуальну мережу Windows, а далі — через мережеве підключення до Інтернету. Технологія NAT дозволяє пристроям і віртуальним середовищам із приватними адресами обмінюватися даними із зовнішніми серверами.

Отже, різниця між локальною та публічною IP-адресами є очікуваною для такого мережевого середовища.
